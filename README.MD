# 🏠 Room Planner (RenovatorCore)

Помощник по ремонту: рассчитывает площадь стен, количество обоев, бюджет и визуализирует комнату.  
Реализован на Java с применением **TDD** и AI-ассистента.  
Доступен как консольное приложение и Telegram-бот.

## 📌 Цели проекта

- Освоить классический TDD (красный → зелёный → рефакторинг) на реальной задаче
- Научиться проектировать иммутабельную предметную модель, покрытую тестами
- Получить опыт разработки многослойного приложения (модель, CLI, бот)
- Внедрить поддержку нескольких языков (i18n) и постоянное хранение данных
- Подготовить фундамент для будущего расширения (сложные формы комнат, бюджет, визуализация)

## 🚀 Возможности (текущее состояние)

- ✅ Создание прямоугольной комнаты с проёмами (окна, двери)
- ✅ Указание точного расположения проёмов на стене (расстояние слева и от пола)
- ✅ Расчёт площади пола, объёма, общей и чистой площади стен
- ✅ Подсчёт необходимого количества рулонов обоев
- ✅ ASCII-визуализация плана комнаты (масштабируемая)
- ✅ Консольный интерфейс (CLI) с набором команд
- ✅ Telegram-бот с такой же функциональностью
- ✅ Интернационализация (русский и английский) с возможностью переключения в сессии
- ✅ Сохранение комнат между перезапусками (JSON-файлы, легко заменить на БД)
- ✅ Более 50 модульных тестов (JUnit 5 + AssertJ)

## 🛠 Технологический стек

- **Java 17+**
- **JUnit 5**, **AssertJ** — тестирование
- **Telegram Bots API** (pengrad/java-telegram-bot-api)
- **Jackson** — сериализация в JSON (для хранения)

- **Git**, **GitHub** — контроль версий

## 🧱 Архитектура

| Слой | Компоненты | Ответственность |
|------|------------|-----------------|
| **Модель** | `Room`, `Wall`, `WallOpening`, `Opening` | Геометрия комнаты, расчёты, визуализация |
| **Хранение** | `RoomRepository` (интерфейс), `FileRoomRepository`, `InMemoryRoomRepository` | Сохранение/загрузка комнат |
| **Логика интерфейса** | `RoomCli`, `MessageProvider` | Обработка команд, интернационализация |
| **Бот / CLI** | `BotService`, `RoomBot`, `Main` | Управление сессиями, запуск бота или консоли |

Все слои зависят от абстракций, что позволяет легко заменять реализацию (например, перейти с файлов на БД).

## ⚙️ Запуск проекта

### 1. Клонирование и сборка

```bash
git clone https://github.com/akasalinsky/contract-generator.git
cd room-planner
mvn clean package
```

### 2. Запуск консольной версии

```bash
java -cp target/classes org.example.Main
```

Введите `create Hall 4000 3000 2700`, затем `describe`, `plan 100` и т.д.  
Команда `exit` завершает работу.

### 3. Запуск Telegram-бота

Получите токен у `@BotFather`.

Создайте файл `.env` в корне проекта (или задайте переменные окружения):

```text
BOT_TOKEN=ваш_токен
BOT_USERNAME=имя_бота
```

Запустите класс `org.example.BotMain`.

Напишите боту `/start`.

## 💬 Команды (CLI и бот)

| Команда | Аргументы | Описание |
|----------|-----------|----------|
| `create` | `<имя> <длина> <ширина> <высота>` | Создать прямоугольную комнату |
| `describe` | – | Описание комнаты и площади |
| `plan [масштаб]` | масштаб в мм/символ (по умолчанию 500) | ASCII-план комнаты |
| `area` | – | Площадь пола |
| `wallpaper` | `<ширина_рулона> <длина_рулона>` (в мм) | Количество рулонов обоев |
| `lang` | `ru` или `en` | Сменить язык |
| `exit` | – | Завершить сессию (в боте — сброс, комната сохраняется) |
| `/start` | – | Приветствие (бот) |
| `/delete` | – | Удалить сохранённую комнату (бот) |

В боте все команды без слеша, кроме `/start`, `/lang`, `/delete`.

## 🌐 Интернационализация

Поддерживаются русский и английский языки. Все строки вынесены в `messages_*.properties`.

По умолчанию используется английский. Переключить язык можно командой `lang ru` / `lang en`.

При смене языка пересоздаётся сессия с новым `MessageProvider`.

## 💾 Хранение данных

Сейчас: каждая комната сохраняется в отдельный JSON-файл в папке `data/` (`chat_<ID>.json`).

Расположение можно задать через `ROOM_STORAGE_PATH` в `.env` (по умолчанию `./data`).

Для замены хранилища реализуйте интерфейс `RoomRepository` и передайте другую реализацию в `BotService` — бизнес-логика останется неизменной.

## 🧪 Тестирование

Проект построен на принципах TDD. Для каждого компонента написаны unit-тесты:

- Модель: `Room`, `Wall`, `WallOpening`, `Opening` — валидация, расчёты, визуализация.
- CLI: `RoomCli` — обработка команд, форматирование ответов.
- Бот: `BotService` — сессии, переключение языка, загрузка/сохранение.
- Хранилище: `RoomRepository` — тесты с in-memory реализацией.

Запуск всех тестов:

```bash
mvn test
```
